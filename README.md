# ФСП Job Board

Платформа подбора IT-специалистов с **обратной механикой**: кандидаты распределяются по категориям (специализация × грейд) по результатам адаптивного теста, а работодатель сам находит нужную категорию и выходит на конкретного человека с предложением и зарплатой. Профиль усиливают достижения в соревнованиях Федерации спортивного программирования (привязка ФСП ID).

## Ключевые механики

**Тестирование, устойчивое к утечкам.** Задание — шаблон-генератор: числа, данные и код меняются для каждого кандидата, правильный ответ вычисляется (код и SQL исполняются). 175 семейств заданий; адаптивный тест (IRT 3PL + классификационный CAT) решает, выше ли способность кандидата порога заявленного грейда, в среднем за ~18 заданий. Состав теста — ядро специализации (общее для всей категории) и модули по заявленному стеку: проверяется то, что кандидат заявил, чужой язык не подставляется. Грейд по результату не понижается; смена подтверждённого грейда — не чаще раза в 90 дней. Мониторинг утечек (CUSUM) и онлайн-перекалибровка параметров заданий (MML-EM).

**Подбор и выход на контакт.** Работодатель описывает потребность текстом → NLP выделяет стек, специализацию и грейд → рекомендованные категории и ранжированная подборка с объяснением («подтверждено тестом», «заявлено», «чего не хватает», «вилка в ожиданиях») → уточнение фильтрами без потери подборки (версии) → приглашение с обязательной вилкой «от–до». Контакты кандидата открываются только после принятия приглашения или собственного отклика.

Ранжирование (формула v5): требования вакансии весят по их специфичности в категории, жёсткие расхождения (основной стек, формат, вилка) работают как «ворота». Опционально — гибрид с локальным кросс-энкодером (`FSP_RANKER=hybrid`).

**Валидация** (`make validate`: синтетическая популяция со скрытой истиной и намеренно рассогласованной моделью ответов):

| | Наша механика | Поиск по ключевым словам (BM25) |
|---|---|---|
| Качество подборки NDCG@10 | **0.72** | 0.20 |
| Ожидаемые принятые приглашения в топ-10 | **4.0** | 1.0 |
| Ложные подтверждения грейда при утечке 50% банка | **26%** | фиксированный тест — 79% |

Точность грейда — 69% точно и 99.8% в пределах ±1 ступени при завышении 4.5%; повторное прохождение — взвешенная κ 0.85.

**Бенчмарк подбора со слепой разметкой** (живые тексты резюме и вакансий, nDCG@10 у независимого асессора): формула v5 — **0.79**, v5 + кросс-энкодер — **0.81**, исходная формула v1 — 0.70, лучший нейросетевой бейзлайн — 0.65.

## Быстрый старт (Docker Compose)

Требования: Docker 24+ с Compose v2, ~4 ГБ свободной RAM, свободные порты 80, 8000, 8025, 8080, 8090.

```bash
git clone git@github.com:Izymka/fsp-job-board.git && cd fsp-job-board
cp .env.example .env    # для локального запуска можно ничего не менять
make up                 # = docker compose up -d --build + HTTP для админки Keycloak; первая сборка ~3–5 мин
```

| Адрес | Что там |
|---|---|
| http://localhost | Платформа |
| http://localhost/api/docs | Swagger UI (OpenAPI) |
| http://localhost:8080 | Keycloak (админ — из `.env`, по умолчанию `admin` / `admin`) |
| http://localhost:8025 | Mailpit — письма подтверждения email и уведомления |
| http://localhost:8090/docs | Реестр ФСП (имитация) |

При старте бэкенд применяет миграции и загружает демо-данные: ~300 кандидатов, прошедших симулированный тест, 7 компаний с вакансиями, регулярные задания, историю приглашений.

### Демо-аккаунты (тестовые учётные данные стенда)

| Логин | Пароль | Роль |
|---|---|---|
| `employer@demo.fsp` | `demo12345` | Работодатель, компания «Рубль+» |
| `maria@demo.fsp` | `demo12345` | Кандидат Backend · Middle с привязанным ФСП ID |
| `candidate@demo.fsp` | `demo12345` | Новый кандидат — для показа онбординга |
| ФСП ID `fsp-000123` | `demo12345` | Участник ФСП с достижениями (кнопка «Привязать ФСП ID») |
| ФСП ID `fsp-000999` | `demo12345` | Участник без истории ФСП |

Новая регистрация: «Регистрация» → форма Keycloak → письмо в Mailpit → ссылка подтверждения → выбор роли.

Полезные команды: `make ps`, `make logs`, `make seed`, `make reset` (пересоздать демо-данные), `make down`.

## Локальный запуск без Docker

Требования: Python 3.12, [uv](https://docs.astral.sh/uv/), Node.js 20+.

```bash
uv sync --all-packages   # Python-зависимости всех модулей
make dev                 # реестр ФСП :8090, API :8000, фронтенд :5173 в одном терминале; Ctrl+C — остановить всё
```

Откройте http://localhost:5173 (Swagger — http://localhost:8000/api/docs). Можно запускать и по отдельности, каждый в своём терминале: `make dev-registry`, `make dev-backend`, `make dev-frontend`.

В этом режиме используется SQLite и `AUTH_MODE=dev`: страница входа предлагает демо-аккаунты без пароля, Keycloak не нужен. Это **только для локальной отладки**; привязка ФСП ID — демо-кнопкой по номеру.

## Сценарий проверки

1. **Кандидат:** войти `candidate@demo.fsp` → роль «Ищу работу» и согласие на обработку ПДн → опрос (специализация, стек, ожидания, заявленный грейд) → «Тест и грейд» → пройти тест → категория, например «Backend · Middle» (или тест на уровень ниже).
2. **Работодатель:** войти `employer@demo.fsp` → «Подборки» → «Новая подборка» → вставить текст потребности («Вставить пример») → «Показать подборку» → рекомендованные категории и кандидаты с объяснением → фильтр «есть ФСП» → откат версии → «Пригласить».
3. **Контакт:** войти `maria@demo.fsp` (или кандидатом из шага 1) → «Приглашения» → открыть (статус «просмотрено») → «Принять» → у работодателя в «Приглашениях» появились ФИО и контакты.
4. **Отклик:** кандидат → «Вакансии» → откликнуться → работодатель → «Вакансии» → «Отклики».
5. **Механики:** публичные страницы «Тест из описания вакансии» (`/test-demo`) и «Как это работает» (`/how-it-works`).

## Тесты, линтер, валидация

```bash
make test           # тесты ML-ядра и сквозные тесты API + сборка фронтенда
make lint           # ruff
make validate       # процедура валидации: отчёт и графики (~2 мин)
make bench-eval     # метрики бенчмарка подбора по сохранённой разметке
```

## Структура репозитория

```
ml/                 ML-ядро (пакет fspml): тестирование IRT/CAT и банк заданий, подбор, NLP, валидация, бенчмарк
backend/            API на FastAPI (модульный монолит), миграции Alembic, seed-данные, тесты
frontend/           React + TypeScript: кабинеты кандидата и работодателя
fsp-registry-mock/  имитация реестра ФСП с предложенной схемой данных
keycloak/           realm-ы Keycloak: платформа (fsp-jobs) и имитация ФСП ID (fsp-id)
```

Стек: Python 3.12, FastAPI, SQLAlchemy 2, PostgreSQL 16, Keycloak 26, React 19, TypeScript, Tailwind CSS 4. ML работает локально на CPU: персональные данные кандидатов не передаются во внешние сервисы (152-ФЗ).
